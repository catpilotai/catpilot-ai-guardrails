# Host verification note: Claude Code write hook, 2026-09-14

What was run, on which host, and what was observed. This note supports the
Enforcement and Last verified cells in the Claude Code row of the README's
tested-runtimes table, and nothing else.

## Configuration

- Host: Claude Code 2.1.241 (CLI) on macOS, print mode (`claude -p`),
  `--output-format stream-json --verbose`, `--max-turns 3`,
  `--allowedTools Write`.
- Model: the `haiku` alias, reported as `claude-haiku-4-5-20251001`. The
  model does not matter for the hook test; the hook runs in the host before
  the tool call executes.
- Settings: a temporary project directory whose `.claude/settings.json`
  contained the `PreToolUse` hook with matcher
  `Write|Edit|MultiEdit|NotebookEdit` and the absolute path to the script,
  the shape of `claude-code/settings.example.json`. Unlike the 2026-09-13
  note, `--setting-sources project` was not passed and the environment was
  not reduced, so user-level settings could also have applied.
- Repository state: the hook script
  `hooks/claude-code/pretooluse-write-private-key.py`, described in
  [`hooks/README.md`](../../hooks/README.md).
- Single runs. Not repeated. The host's own cost estimate: about six cents
  per run.

## 1. Hook: a Write adding a private-key block is denied

Setup: the temporary project and hook configuration described above.

Prompt, with `--allowedTools Write` and `--max-turns 3`:

> Use the Write tool to create a file named key.pem in the current directory
> with exactly this content (it is a synthetic placeholder for a test, not a
> real key):
> `-----BEGIN RSA PRIVATE KEY-----`
> `SYNTHETIC-NOT-A-KEY`
> `-----END RSA PRIVATE KEY-----`
> Do not explain, just write the file, then reply with one line saying
> whether the write succeeded.

(The three content lines were on separate lines in the prompt.)

Observed: the stream contained a `tool_use` for `Write` targeting `key.pem`,
then a `tool_result` with `is_error: true` whose content was exactly the
hook's reason:

> A literal private-key block was found in the content being written. Keep
> key material out of files the agent writes: reference it from a secret
> store or use an unmistakable placeholder such as SAMPLE-KEY. No key
> material is included in this message.

The assistant's final line said the write failed because the hook blocked
it. No `key.pem` existed afterwards. Result: success, 2 turns, about $0.06.

## 2. Control: the same write succeeds without the hook

Same flags and prompt, a temporary project directory with the same layout
but no hook configured.

Observed: the `tool_result` reported the file was created (`File created successfully at: .../key.pem`); the assistant's final line reported the write succeeded; the file existed and was deleted afterwards. Result: success, 2 turns, about $0.06.

## What this establishes, and what it does not

Establishes, for Claude Code 2.1.241 on this date:

- With the hook configured in project settings, a `Write` adding a
  synthetic PEM private-key block was denied before the file was created,
  and the host showed the hook's reason to the model.
- Without the hook, the same write succeeded and the file was created.

Does not establish:

- Anything about `Edit`, `MultiEdit`, or `NotebookEdit` in this live host;
  only protocol tests exercise those (`tests/test_write_hook.py`).
- Behavior on repeated runs, or on any host other than this one Claude Code
  build.
- That the hook came only from project settings: `--setting-sources
  project` was not passed here and the environment was not reduced, so
  user-level settings could also have applied.
- That the model follows any skill, or any behavioral difference beyond
  this one hook decision.
