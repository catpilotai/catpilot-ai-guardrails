## What this shows

- **The zipapp layout works on macOS.** On Claude Code, Codex and Copilot
  CLI, the tools ran the checks from `catpilot-guard.pyz`, the default of
  `install.sh` since #158, with the interpreter recorded in each hook command.
- **The hooks with the #137 reader denied every built-in probe on Claude Code
  and Codex.** The build included #137. The probes are the same items as on
  2026-11-16/17; none of them is a compound command of the kind #137 added,
  so this shows the reader did not stop the earlier forms from being caught,
  not that its new forms are caught on a host.
- **`deploy_host`, `package_registry` and `cloud_account` in `block`, and an
  exception, acted on Claude Code, Codex and Copilot CLI**, with a control
  run on each.

## What this does not show

- **Copilot CLI's built-in checks, file-write check and `protected_branch`
  rules in this build.** The model declined the whole nine-item probe. They
  were last seen acting on Copilot CLI 1.0.113 on 2026-11-17/18, from hook
  files, before #137 and the zipapp
  ([note](2026.11.17-host-check-company-rules.md)).
- **The refusal of a Python that someone other than root can change.** The
  override was set.
- **More than one form per kind.** Item 11 was a `git push` to a `heroku`
  remote; items 12 and 13 were environment assignments. The other commands
  the hook reads (`vercel`, `--registry`, `gcloud --project`, an ARN, ...)
  were not run on a host.
- **The commands #137 newly reads** (`if`, loops, `{ }`, functions,
  comments).
- **`ask`, on any tool.**
- **Interactive sessions,** `/status`, `/context all` and `/hooks`, and the
  `resume`, `clear`, `compact` and `fork` session sources.
- **Linux, Windows,** the desktop apps, IDE extensions and cloud agents.
- **Resistance to a deliberately disguised command.**
