managed Codex `PreToolUse` row of the verification-status table

**Evidence lines.**
- **Six `deny` lines per tool,** each carrying that session's id:
  - five on `Bash`: two from the force-push rule, then the `rm -rf` rule,
    the terraform rule and the AWS access key ID rule;
  - one `private-key-block` line.
- **The private-key line names the tool that made the edit:** `Write` on
  Claude Code, `apply_patch` on Codex.
- **The Codex lines say `host: "codex"`.**
- No line carried a command, a path or file content, and the control wrote
  no line.

**What this shows for Codex:**
- Codex loaded the managed hooks with no trust step.
- They ran on `Bash` and on `apply_patch`.
- The write check read the key block from the patch Codex sent in
  `tool_input.command`: until this run, that patch format was known only
  from the documentation.

**Inert probes:** every probe does nothing even if it runs. The folders had
no remote, `terraform` had nothing to apply, the path did not exist, the key
is AWS's documentation example, and the key block was synthetic.

## Findings

- **As on the earlier run today, Claude Code repeats expired rules.** It
  labels them as expired, but they stay in the managed `CLAUDE.md`. Codex
  never receives them.
- **Codex's expired answer also said "the rules lookup is unavailable".** No
  server was reachable and no MCP server was loaded, so this refers to the
  missing lookup, not to a failed call.
- **The evidence lines from the hooks still carry
  `source: "claude-code-hook"` on Codex.** By design, `host` names the tool.

## What this does not show

- **Interactive sessions.** These were headless (`claude -p`, `codex exec`),
  with the owner's own settings, rules and MCP servers left out. People's
  interactive sessions load those, and an owner's allow rules or a Codex
  `danger-full-access` sandbox can change what runs after a hook allows
  something.
- **`/status`, `/context all` and `/hooks` output.** Nor the `resume`,
  `clear`, `compact` and `fork` session sources, nor the "could not be
  loaded" path.
- **Under the default `"first-wins"` behavior,** whether the managed files
  apply when claude.ai managed settings also apply.
- **Codex's `Edit` and `Write` matcher aliases.** The managed file names only
  `^apply_patch$`.
- **A without-hook control run for these probes.**
- **Linux, Windows, the desktop apps, IDE extensions, cloud sessions,
  Copilot CLI.**
- **Resistance to a deliberately disguised command.**
