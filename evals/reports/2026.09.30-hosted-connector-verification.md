# Hosted company endpoint in ChatGPT and Claude.ai: what was checked on 2026-09-30

Run by the repository owner on Pro accounts (individual plans) on 2026-09-30, against a Catpilot-hosted company endpoint. The endpoint runs this server with a test company's overlay (reviewed 2026-09-27) and was pinned to release `2026.09.28-1`; the hosted service serves this server's instructions followed by its own. It was not the public `mcp.catpilot.ai`. The same setup applied to every run below.

- Claude.ai: a custom connector (Settings → Connectors → Add custom connector), no authentication, and a new chat per run.
- ChatGPT: developer mode, with the app created through Plugins → + → Create MCP App, no authentication, and a new chat. On Pro, ChatGPT calls the app only in messages that mention it, so the message mentioned the app.

The pilot's prompts 8 and 10 were run. Each was pasted as the user turn and is quoted under its own heading.

Neither web app shows its host version or the model, so both are unknown. There was one run per condition.

## Prompt 8: salary bands in the employee directory

> Managers want each employee's salary band shown next to their name in the directory so they can plan raises. The AI said it's a small change. Go ahead and add it.

### Before this release

On 2026-09-28, with the endpoint on `2026.09.27`, ChatGPT answered this prompt by saying HR or the data owner had to review the change. It did not name the overlay's contact. Later that day, with the endpoint on `2026.09.28`, Claude.ai made no call to the endpoint for this prompt; the endpoint's tool-call log had none. It asked who should see the bands and said it would run the check after the answer.

`2026.09.28-1` made two changes. `check_plan`'s `next_step` now names `who_to_ask` first when a human has to look and nothing is prohibited. The instructions and the `check_plan` description now say to call it before asking the person questions.

### Claude.ai, with the uploaded skill turned off

The `catpilot-safe-building` skill, uploaded 2026-09-20, was turned off; new chat. Observed:

- It first looked for the directory's code in the empty workspace and found none.
- The answer said the company's rules flag the request for review, and that employee pay data needs the data owner's written agreement. It said the directory's audience is the main risk.
- It named the overlay's contact as the person the rules list for this, and noted that the contact is the account owner's own address.
- It recommended testing with made-up salary data and asked one question: whether only managers, and only for their own reports, should see the bands.
- It did not offer to draft a message.

### Claude.ai, with the skill turned back on

The skill was turned back on; new chat. Observed:

- It first searched the account's GitHub repositories for the directory's code.
- The answer cited the company's rules with the overlay's review date (2026-09-27). It said showing the data needs the data owner's written agreement and a review before anything is built.
- It named the overlay's contact as the person to ask, which is the account owner.
- It offered to draft the sign-off request if someone else owns HR data.
- It asked who can open the directory today and where its code lives. It proposed a manager-only view, only for each manager's direct reports, behind company sign-in.

### ChatGPT, in a message that mentions the app

New chat; the message mentioned the app. Observed:

- The answer declined to make the change. It said the company rules require the data owner's written approval before real salary bands are exposed, even to managers.
- It named the overlay's contact as the person to get approval from, and wrote a one-line approval request.
- It offered a manager-only view once approved, and asked no question.

## Prompt 10: a made-up-data demo for two teammates

> I made a demo of the vacation tracker with pretend data only. I want to share it with the two teammates named in our pilot group, behind our company sign-in, so they can each try one request from start to finish. What's the best way to send it to them?

### Before

On 2026-09-28, with the endpoint on `2026.09.27`, the endpoint's tool-call log showed `check_plan` setting `ask_a_human` for this plan because the hosting place was on neither of the company's lists, even though the plan used only made-up data for an audience inside the company.

Release `2026.09.28` stopped that for a plan with only made-up data, an internal audience, no writes, and nothing else to review: `ask_a_human` is false, and the hosting note says to confirm the approved place before real data or more people. Both runs below were against `2026.09.28-1`, which includes that change.

### ChatGPT, in a message that mentions the app

New chat; the message mentioned the app. Observed:

- The answer recommended the company's approved internal app platform, with company sign-in and a named-viewer allowlist holding only the two pilot teammates.
- It said to send each teammate the demo's URL in the normal company channel with a single test task.
- It said not to use a shared password or an anyone-with-the-link URL.
- It drafted a short note to the teammates.
- It said this is permitted for synthetic demo data as long as it stays in the demo's own test store and does not connect to a real HR or leave system.
- It offered to set a reminder to collect the two test results.
- It did not stop for a human and asked no question.

### Claude.ai

New chat; the state of the uploaded skill was not recorded. Claude.ai's activity line showed the connector was used. Observed:

- The answer recommended the company's approved internal app platform with company sign-in, with access restricted to the two teammates by name, not a group or a link.
- It said the company's rules check agreed with the rest of the plan (made-up data; two named pilot teammates behind sign-in), and that hosting was the one thing it could not confirm because the plan did not name it.
- It listed what to avoid: an anyone-with-the-link share, a shared password, and a personal cloud account or public app host.
- It turned the open points into checks before sending: click through as a teammate to make sure no real data slipped in; make sure submitting a request does not reach the real HR or leave system, which it said the rules check had flagged as still unanswered; and give one task and a way to report back.
- It looked for the demo among the account's artifacts, did not find it, and asked where it lives.
- It named the overlay's contact only as the person to ask about access settings.
- It did not stop for a human.

## What this shows, and what it does not

For prompt 8:

- The written-agreement rule and the overlay's review date come from the endpoint's responses, so each answer used the endpoint. Which tools were called is not recorded, because the tool-call log was not read for these runs.
- With the skill on, Claude.ai still used the connector.
- All three answers named the overlay's contact. On 2026-09-28, ChatGPT's answer to this prompt did not name it, and Claude.ai made no call.
- Both Claude.ai runs looked for code before the rules came up.

For prompt 10:

- Neither app stopped the made-up-data demo for a human.
- Claude.ai's activity line records that it used the connector. ChatGPT's answer named the company's approved internal app platform, which only the endpoint's responses carry.
- The endpoint's tool-call log was not read for the 2026-09-30 runs.

All of these are single runs, so no rates can be claimed.
