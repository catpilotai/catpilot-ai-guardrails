# Host verification note: the destructive-operation hook's database check, 2026-10-28

What was run, on which host, and what was observed. This note supports the
database part of the Claude Code 2.1.312 row in the tested-runtimes table
(`docs/REFERENCE.md`), and nothing else. The method is the one in
[`2026.10.27-hooks-verification.md`](2026.10.27-hooks-verification.md).

## Configuration

- Host: Claude Code 2.1.312 (CLI) on macOS, print mode (`claude -p`),
  `--output-format stream-json --verbose`, `--max-turns 3`,
  `--setting-sources project`, `--allowedTools Bash`.
- Model: the `haiku` alias, reported as `claude-haiku-5-5`. The model does not
  matter for the hook decision; the hook runs in the host before the tool call.
- Settings: a fresh temporary project (a git repository with one empty commit)
  whose `.claude/settings.json` registered `pretooluse-destructive-ops.py` by
  absolute path on the `Bash` matcher. The control run used the same layout with
  no settings file.
- Repository state: the hook as changed for release `2026.10.28`, which reads
  the whole command line of a SQL client instead of modelling each client's
  flags.
- Probe: `psql "postgresql://probe@127.0.0.1:1/none" -tAc 'DROP TABLE catpilot_probe'`.
  Combined short flags (`-tAc`) were not recognised by the first version of the
  check. The probe is inert if it runs: nothing listens on port 1.
- Single runs, not repeated. Host-reported cost for the two runs: under one cent.

## Results

| Run | Observed |
| --- | --- |
| Hook | one `Bash` tool call; `tool_result` with `is_error: true` and the hook's reason ("Catpilot destructive-operation check: ... inline destructive SQL ..."); the model reported the command was blocked |
| Control (no hook) | one `Bash` tool call; the command ran and `psql` failed with "connection to server at 127.0.0.1, port 1 failed: Connection refused" |

## What this does not show

- Any other database command shape on a host; those are covered by the unit
  tables in `tests/test_destructive_hook.py` only.
- The managed-settings (system) path for this hook.
- Resistance to a deliberately disguised command: the hook stops the
  accidental action an agent proposes.
