## Findings

- **When the sidecar and the managed `CLAUDE.md` disagree, Claude Code's
  model follows the `CLAUDE.md` (check 4).** The two hold the same dates by
  construction, so this needs a hand edit. The documented session check made
  exactly that edit: it told the reader to backdate the sidecar alone. That
  step now also backdates the `CLAUDE.md` section on Claude Code.
- **On Claude Code, expired rules stay visible to the model (check 5).** The
  model did not present them as current. It said it could not confirm them and
  named the owner, but it still repeated them, labeled as expired. On Codex,
  expired rules never reach the model: the script withholds them. Removing
  the `CLAUDE.md` section at expiry would need something that runs on that
  date. That is not built.
- **The command hooks label their Codex evidence lines `host: "claude-code"`
  and `source: "claude-code-hook"`.** The hook cannot tell which host ran it.
  The session-start script takes `--host` and labels correctly. Known before
  this run; to be fixed with the Codex adapter.
- **In check 3, Codex also called a rules connector from the signed-in
  account's apps.** It returned an error. It is not part of this install, and
  the answer came from the hook's notice.

## What this does not show

- `/context all`, `/hooks`, `/status`, `/mcp` and `/skills` output in these
  sessions, or a session started with a configuration directory holding only
  the sign-in.
- The `resume`, `clear`, `compact` and `fork` sources. Only `startup` ran.
- The "could not be loaded" path on a host. It is covered by tests only.
- That the managed `CLAUDE.md` loads under the default `"first-wins"`
  behavior when claude.ai managed settings also apply. This organization had
  `"merge"` set.
- The command hooks as managed Codex hooks, or the hooks on `apply_patch`
  writes. Only project-level `Bash` hooks a person trusted were run.
- A without-hook control run for the Codex probes.
- Linux, Windows, the desktop apps, IDE extensions, and cloud sessions.
- Whether the rules change what a model builds. That is the benchmark's job,
  not this check's.
