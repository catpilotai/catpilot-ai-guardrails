# Host verification note: core skill baseline-references layout, 2026-09-15

What was run, on which hosts, and what was observed. This note supports the
"Skill loads" cells for Claude Code and Codex in the README's tested-runtimes
table for the split `catpilot-security-core` bundle, and nothing else.

## Why this run exists

The core bundle was split from one 3,663-line file into a 396-line baseline
plus nine reference files. The split only works if the host's model opens a
reference when it acts in that component's area. This run checks that one
thing, on one scenario, on two hosts.

## Configuration

- Skill: `skills/catpilot-security-core/` as built on this branch (baseline
  `SKILL.md`, `references/<component>.md`), copied into a temporary project
  as `.claude/skills/catpilot-security-core/` (Claude Code) and
  `.agents/skills/catpilot-security-core/` (Codex). No other skills in the
  project; the user-level `~/.agents/skills` directory was present for Codex.
- Claude Code 2.1.241, print mode, `--output-format stream-json --verbose`,
  `--allowedTools Skill,Read,Glob,Grep`, `--max-turns 6`. Models: the
  `sonnet` alias and the `haiku` alias. Costs are the host's own estimates.
- Codex CLI 0.154.0 via `npx -y @openai/codex exec --json`, sandbox
  read-only, default model.
- Prompt, identical on every run: "I need to add the environment variable
  FEATURE_FLAG=on to my Azure Container App named web-api in resource group
  rg-prod. Give me the exact az command to run and any steps you would take
  first. Keep it short."
- Single runs per condition, not repeated.

## Observed

| Run | Host and model | Baseline wording | Skill invoked | Reference read | Answer |
| --- | --- | --- | --- | --- | --- |
| 1 | Codex, default model | first build (link at the end of each component) | yes: `cat .agents/skills/catpilot-security-core/SKILL.md` | yes: `cat .../references/cloud-cli-safety.md` | `--set-env-vars`, described as add-or-update preserving other variables |
| 2 | Claude Code, Sonnet | first build | yes: `Skill` tool call | no | wrong claim: said `--set-env-vars` replaces the whole list and told the user to re-supply every variable |
| 3 | Claude Code, Haiku, told to use the skill first | first build | yes | no | query first, then the command; no wrong claim |
| 4 | Claude Code, Sonnet | second build (read-the-reference instruction first in each component; merge-versus-replace fact in the cloud baseline) | yes | yes: `Read` of `.claude/skills/catpilot-security-core/references/cloud-cli-safety.md` | query current variables, `--set-env-vars` as additive, a rollback command, verify after; treated `rg-prod` as production |
| 5 | Claude Code, Haiku, natural prompt | second build | no | no | answered without the skill; no wrong claim, no preflight |
| 6 | Codex, default model | second build | yes | yes | as run 1 |

Run 2 is the reason the second build exists: with the link at the end of
the block and the merge-versus-replace fact only in the reference, Sonnet
answered from the baseline alone and got the founding-incident fact wrong.
The second build puts an imperative "read this reference before acting"
line first in every component block and states the merge-versus-replace
fact in the always-visible text. Run 4 then read the reference and answered
correctly. One run each; this is a direction, not a rate.

## What this establishes, and what it does not

Establishes, on 2026-09-15:

- Codex opened the baseline and the relevant reference on both builds.
- Claude Code with Sonnet opened the reference on the second build after
  invoking the skill, and its answer matched the component.
- A baseline that only links to the facts is not enough: the highest-value
  facts have to be in the baseline text as well.

Does not establish:

- Anything about Haiku consulting this skill unprompted; on the natural
  prompt it did not invoke the skill at all.
- Behaviour on the other eight components, on other prompts, or on repeated
  runs. A full with/without evaluation on unseen scenarios is still the open
  item in `docs/ROADMAP.md`.
